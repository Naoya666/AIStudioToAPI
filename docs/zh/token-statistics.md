# PG / Build Token 统计与双重预算

更新时间：2026-11-02。本次只改代码、测试、文档；没有部署、重启或修改生产账号及额度。

## 预算口径

下面数值来自本次用户提供的账号观测，作为面板估算基线，不是本项目真实上游验收或 Google 保证。Google 的[订阅功能说明](https://blog.google/innovation-and-ai/technology/developers-tools/google-one-ai-studio/)确认订阅可提高 AI Studio 使用上限；公开的 [Gemini API rate limits](https://ai.google.dev/gemini-api/docs/rate-limits)不能直接替代浏览器 Playground / Build 代码助手的具体配额。因此不混用 API key 计费项目、运行 Build App 的代理生成配额与代码助手配额。

| 通道 / 模型                 | Free 次数 / token 日预算 | Pro 次数 / token 日预算 |
| --------------------------- | ------------------------ | ----------------------- |
| PG `gemini-3.1-pro-preview` | 10 / 5,000,000           | 50 / 13,000,000         |
| PG `gemini-3.8-flash`       | 100 / 11,000,000         | 150 / 25,000,000        |

| PG `gemini-4-argon`         | 不开放                   | 50 / 15,000,000         |
| Build 全部模型共享          | 未知                     | 次数未知 / 20,000,000   |

Ultra / Ultra20 的次数和 token 额度保持未知，移除旧的 500 / 100 / 200 次推算。未列入上表的旧 PG 模型只保留原有次数估算，token 不外推。未知账号仍沿用项目既有 Free 权限默认值；历史 token 统计中的账号层级缺失则标为 `unknown`，不据此认定其真实订阅层级。

PG 按“账号 × 规范模型”分别统计次数与 token。`build/X`、`build-st/X`、思考、流式、anti 等别名不产生重复额度；**同账号所有 Build 模型共用 2000 万池**，不可将每个 Build 模型卡片的池余额相加。PG 与 Build 分开。

模型白名单与账号权限不自动改变，只有已经授权的账号进入面板预算汇总；上表列出预算不表示自动开放该模型。

这次没有新增根据 token 估算自动封禁账号的逻辑；已有上游 429、模型冷却与账号失效机制继续处理真实错误。

## 采集与不重复计数

PG 在 `PlaygroundTransport` 解码上游 usage 时采集，早于 OpenAI 工具校验和输出格式转换，覆盖现有调度路径中的流式、非流式及各协议。工具校验失败、取消或任务异常前已经收到的 usage 同样保留。取自已知协议字段：prompt、candidate、total，以及存在时的 cached、thoughts、tool-use prompt。cached 与 tool-use 的 wire 位置同时核对了本地参考项目 `Mag1cFall/AIStudio2API` 的 `event.go`（MIT，参考提交沿用双通道文档）。

Build 读取同任务累计快照，只按累计字段的增量更新，不对每次轮询再次计费；任务读取恢复不创建新生成，也不增加 token 消耗副本。

每次上游尝试单独记录所属账号、规范模型、开始观测时的账号层级与本地日期。换号重试分别归属各自账号，不把所有消耗记给最后账号。各次尝试的已知值合并为客户端请求的统计；有尝试缺少 usage 时保留 `partial`，已知部分也不会被最终结果覆盖为 0。PG 回调在尝试开始时捕获，旧尝试的迟到响应不会写入新尝试账号。

- 总 token 优先采用上游 `total_tokens` / `totalTokenCount`，不通过字符串长度估计，也不凭缺失字段伪造总数。
- 缓存是输入的子集，思考是输出的子集；统计中保留子项，不能再次加到总 token。
- 缺失的输入 / 输出 / 缓存 / 思考分别保留未知；真实返回 0 可以显示 0。
- 本地预算比较暂用上游总 token。**Google 实际额度扣减是否与这个总数完全一致，尚未独立验证**；它不是 Google 账单或权威余额。

## 持久化与历史数据

SQLite 保留原请求 `usage_json`，兼容新增 `token_attempts_json` 和独立 `token_daily` 聚合。按日期、账号、规范模型、账号层级累计输入 / 输出 / 缓存 / 思考 / 总数，以及已知与未知请求覆盖。

首次升级会从仍保留的旧请求 usage 回填一次；没有 usage 的旧请求标为未知，旧记录缺少当时账号层级时标 `unknown`，不能用现在的层级倒填历史。保留了 per-attempt 数据的导入记录按尝试还原；请求 ID 去重避免重复导入重复计数。详细请求按保留期清理后，已建立的 token 日聚合继续保留，方式与项目既有累计请求统计一致。

实时额度面板使用 scheduler 的按账号、模型、日期持久化计数，兼容旧 scheduler state；保留最近三个 token 日窗口，避免零点后的迟到快照清空当前日。升级前的 scheduler 只有请求次数、没有 token 观测，不能自动宣称覆盖完整；SQLite 能恢复的历史统计与实时余额完整性分别展示，不把缺失的旧用量默认为 0。

日期沿用项目 `America/Los_Angeles` 本地统计窗口，处理夏令时。PG / Build 均使用太平洋时间每日 00:00 的本地统计日界线，日额度冷却恢复统一沿用 `SCHEDULER_DAILY_RESET_TIME`（默认 `00:00`）；本地统计窗口不等同于新增的上游验证。没有复制参考项目的北京时间 Build 重置规则。

## 两个面板与 Free Build 后续估算

- 管理面板：调度状态显示次数和 token 两项预算；用量页面新增“Token 统计”，按日期、规范模型、层级和账号查看明细。受已有管理员登录保护的接口为 `GET /api/usage-stats/tokens?day=2026-11-01`，日期为 PT，不含提示词、附件或工具参数。
- Token 明细使用与账号使用分布一致的卡片表格，默认查询 PT 当天。支持规范模型筛选、邮箱部分字符搜索（不区分大小写，`%` / `_` 按普通字符匹配），以及每页 10 / 20 / 50 / 100 条的服务端分页。接口增加 `model`、`email`、`page`、`pageSize` 参数，返回 `total`、`page`、`page_size` 和当天的 `available_models`；省略分页参数时兼容原有调用。
- “账号 × 模型”展开行展示当前模型的今日已知 Token、输入、输出及用量未知的请求数，沿用调度器持久化的 PT 日窗口；没有观测数据时显示未知，不将缺失数据当作零。
- 公示面板：仅展示次数额度，移除 PG / Build 的 Token 预算、已知消耗与明细。Build 日额度确认后可在“预估剩余额度”展示剩余 Token。后台仍保留 Token 数据。多节点合并时，旧 agent 缺少 token 字段、节点过期或不可用均降低覆盖，不能把已知部分当完整总额。沿用 v1 协议的可选字段，旧 agent 可继续接入。
- 已知预算减去已知消耗只能作为上界；有未知用量或未知层级额度时，完整剩余值为 `null`，不显示“剩余 100%”或“无限”。没有任何已知预算时，上界也显示未知。
- Build 卡片明确标注账号共享池。不会按 Build 模型数量重复计算 2000 万预算。

Free Build 当前缺少日上限依据，**不会从 Pro 的 2000 万乘比例推算**。保留配置文件设置，不在前端配置面板展示：

```dotenv
# 默认 0：未知。仅用于展示，不据此阻止请求。
BUILD_FREE_DAILY_TOKEN_ESTIMATE=0
```

确认额度后修改 `.env` 中的配置并重启即可；兼容此前 managed-config 中已保存的值（其优先级高于环境变量，需同步修改或删除旧覆盖）。以后可在真实 Free 账号观测、完整日窗口、明确的 token 限额错误及缓存 / 思考扣减口径均有证据后，手动填写估算；设置非零只改变 Free Build 共享池的面板预算。历史 Free 统计与 unknown 统计分开，便于收集依据，当前不自动生成一个“已验证”的 Free 上限。
