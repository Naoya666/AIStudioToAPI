# 管理端前端统一改造方案

状态：设计稿，尚未实施。本文用于后续任务拆分、界面设计、开发及验收。

编写日期：2026-10-23。

## 1. 改造目标

将现有管理端整理为一套简洁、紧凑、适合长期使用的工具型后台。用户切换首页、账号、节点池、配置、用量和日志时，应看到一致的导航、标题、操作位置、控件和状态表达。

本次首先解决风格和操作组织不统一的问题。成功标准包括：

- 页面使用同一套颜色、字体、间距、圆角及控件尺寸。
- 用户能稳定找到页面主操作、筛选、批量操作和详情入口。
- 桌面端便于查看大量账号、节点和请求记录，移动端仍能完成主要操作。
- 现有数据含义、保存边界、后台任务及实时更新行为保持正确。
- 后续新增页面可复用页面骨架和基础组件，不再单独设计一套样式。

## 2. 现状与原因

以下结论来自源码检查，实施前仍需补充当前版本的桌面和移动端截图作为视觉基线。

| 现状                                           | 代码位置                                                   | 造成的体验问题                                   |
| ---------------------------------------------- | ---------------------------------------------------------- | ------------------------------------------------ |
| 首页、统计、日志和大量手写样式集中在一个页面中 | `ui/app/pages/StatusPage.vue`                              | 页面结构与业务逻辑耦合，局部修改容易形成新的例外 |
| 手写按钮、输入框与 Element Plus 控件并存       | `StatusPage.vue`、`LoginPage.vue` 与账号、配置、节点池组件 | 相同操作的高度、边框、字体和反馈不同             |
| 已有全局变量，但局部仍自行定义间距、圆角和背景 | `ui/app/styles/variables.less`、各组件样式                 | 卡片、标题、工具栏和弹窗缺少共同规则             |
| 自定义主题变量与 Element Plus 主题变量分别使用 | `variables.less`、`ProxyPoolPanel.vue` 等                  | 修改一套主题时，部分组件无法同步                 |
| 导航混用 SVG 和字符图标                        | `StatusPage.vue`                                           | 图标尺寸、笔画和含义不统一，纯图标导航难以辨认   |
| 部分页面有独立路由，部分仅通过页面内标签切换   | `ui/app/router/index.js`、`StatusPage.vue`                 | 刷新、复制链接及浏览器前进后退的行为不一致       |
| 管理端当前强制浅色，仍保留暗色相关样式和依赖   | `ui/app/utils/useTheme.js`、`ui/app/index.js`              | 实现意图不明确，容易误以为暗色已可用             |

## 3. 范围与约束

### 3.1 页面范围

第一批统一管理端公共框架、首页、账号、节点池及配置页；第二批完成用量统计、日志、登录及 VNC 页面外围界面。

匿名公开看板位于独立的 `ui-public/` 工程。本轮不整体重做该页面，也不引入管理端导航、会话或管理数据。后续可共享纯视觉变量和品牌规范，但继续独立构建、部署并保持只读。

### 3.2 行为边界

- 沿用 Vue 3、Vite、Element Plus、LESS，不为统一外观更换技术栈。
- 不在视觉改造中改变请求转发、调度、冷却、账号权限、自动登录或代理绑定策略。
- 沿用现有 API、认证方式、持久化及统计口径。遇到接口缺口时单独记录，不通过前端推测运行状态。
- 保留中文、英文能力；新增和迁移文案集中使用语言资源。
- 第一版以浅色主题验收；不新增可切换但未完整适配的暗色入口。旧暗色样式待使用关系确认后再清理。
- 不直接编辑 `ui/dist/`、`ui-public/dist/`。构建产物按仓库发布约定生成。
- 保留已有作者署名和许可说明。

## 4. 视觉规范

以下数值为首版实现基准。代表页面确认后统一调整，不允许各页面自行产生不同版本。

### 4.1 颜色与层次

| 用途               | 建议值                            | 规则                                   |
| ------------------ | --------------------------------- | -------------------------------------- |
| 页面背景           | `#f6f8fb`                         | 中性浅灰，承载整个工作区               |
| 内容背景           | `#ffffff`                         | 卡片、表格和弹窗                       |
| 次级背景           | `#f1f5f9`                         | 表头、分组、悬停及代码区               |
| 主文字             | `#0f172a`                         | 标题、关键数值、正文                   |
| 次级文字           | `#475569`                         | 说明、辅助信息                         |
| 弱文字             | `#64748b`                         | 时间、单位、次要元数据                 |
| 边框               | `#e2e8f0`                         | 容器与分隔线                           |
| 强调色             | `#2563eb`                         | 主按钮、选中导航、链接及焦点           |
| 成功 / 警告 / 错误 | `#15803d` / `#b45309` / `#b91c1c` | 使用配套浅色背景，并同时提供文字或图标 |

浅色标签的文字与背景分别定义，不直接降低整个组件透明度。禁用态、选中态、悬停态和焦点态需要独立变量；关键正文对比度目标至少为 4.5:1，实施时实际检查。

禁止用大面积渐变、重阴影或多种高饱和色区分常规区块。状态颜色用于表达状态，不用于给不同页面“换主题”。

### 4.2 字体、间距和尺寸

| 项目                  | 规范                                                          |
| --------------------- | ------------------------------------------------------------- |
| 字体                  | 系统无衬线字体栈，覆盖中文；不依赖外部字体服务                |
| 正文 / 表格           | 14px，正文行高约 1.5                                          |
| 辅助说明              | 12px；错误和必要操作说明不缩成难读的小字                      |
| 页标题 / 区块标题     | 24px / 16px；移动端页标题 20px                                |
| 数字与标识            | 指标使用等宽数字；日志、模型 ID、请求 ID 使用等宽字体         |
| 间距                  | 采用 4、8、12、16、24、32px 刻度                              |
| 工作区内边距          | 桌面 24px，平板 20px，手机 16px                               |
| 卡片内边距 / 区块间距 | 默认 20px / 24px；手机卡片内边距 16px                         |
| 圆角                  | 输入框及按钮 6px；卡片和弹窗 10px；胶囊形仅用于明确的状态标签 |
| 控件高度              | 默认 36px，紧凑行内控件 32px；触屏独立操作目标至少 44px       |
| 表格行                | 默认至少 44px，长内容按需增高，不强制所有行固定高度           |
| 阴影                  | 常规内容以边框区分，轻阴影仅用于浮层及确有需要的容器          |

### 4.3 图标

使用一套本地 SVG 图标，统一 20px 画布、笔画粗细和对齐。导航保留文字，清除作为功能图标的棋子字符、Emoji 等替代物。图标按钮必须有可访问名称；必要说明支持触屏点击查看。

## 5. 页面框架与导航

### 5.1 公共框架

桌面采用左侧导航与右侧工作区。导航包含品牌、页面入口，以及位于固定位置的语言与退出操作。顶部不重复堆放与侧栏相同的入口。

每页遵循以下顺序，按实际需要省略区块：

```text
页标题 + 一句说明                         主操作
页面级提示：未保存 / 服务异常 / 数据过期
关键指标或运行摘要
搜索与筛选区
批量操作区：选中数量 + 明确的操作范围
主要内容：表格 / 配置表单 / 日志
分页或更新信息
```

页面主标题只出现一次。表格页铺满可用宽度；表单正文建议限制在约 1040px 并靠左对齐。不得为整站套用适合登录页的窄容器，也不得让宽屏表单无限拉伸。

### 5.2 路由方案

| 导航名称 | 目标路由      | 当前状态                 |
| -------- | ------------- | ------------------------ |
| 概览     | `/`           | 已存在                   |
| 账号管理 | `/accounts`   | 已存在                   |
| 节点池   | `/proxy-pool` | 已存在                   |
| 用量统计 | `/usage`      | 拟新增，当前为页面内标签 |
| 实时日志 | `/logs`       | 拟新增，当前为页面内标签 |
| 系统配置 | `/settings`   | 拟新增，当前为页面内标签 |

保留 `/login` 和 `/auth`。新增路径需验证服务端 SPA 回退、鉴权及刷新直达；迁移页面内跳转和日志设置定位入口，确保刷新、复制链接、前进后退都指向正确页面。

从现有标签迁移到路由不要求同时重写全部数据逻辑。迁移期间仅保留一个当前页面状态来源，避免路由与 `activeTab` 各自控制高亮和轮询。

## 6. 组件与交互规则

### 6.1 共用组件

优先组合 Element Plus，并通过主题变量统一样式。仅为稳定重复出现的模式提供薄封装，不创建第二套表格或表单框架。

| 拟抽取模块                   | 职责                                             |
| ---------------------------- | ------------------------------------------------ |
| `AppShell` / `AppNavigation` | 工作区框架、导航和移动端抽屉                     |
| `PageHeader`                 | 标题、说明及页面操作插槽                         |
| `SectionPanel`               | 区块标题、说明、内容及可选操作                   |
| `FilterBar` / `SelectionBar` | 筛选、已选数量、范围说明及批量操作布局           |
| `StatusBadge`                | 统一状态外观，文本与业务状态映射由调用方明确传入 |
| `MetricCard`                 | 数值、单位、口径和更新时间                       |
| `PageState`                  | 初始加载、空数据、无匹配、错误与重试             |

按钮、输入框、选择框、分页、弹窗和确认框直接使用现有组件库。日志展示、VNC 画布、模型权限矩阵等特殊控件允许保留专用实现，但使用共同的视觉规范。

### 6.2 操作规则

- 同一操作区默认突出一个主要动作；保存、新增等使用主按钮，刷新和导出使用次按钮。
- 删除、清空、重启、批量禁用等操作明确展示对象及范围，并按现有业务要求确认；不为普通刷新增加确认框。
- 提交期间显示进行中状态，阻止同一操作重复提交；服务端成功后才显示成功反馈。
- 完全无数据、筛选无结果、加载失败分别表达，接口失败不得显示成“0 个账号”或“暂无记录”。
- 初次加载使用骨架或加载区；后台刷新保留已有数据、焦点、滚动和选择，并标注失败或过期状态。
- 表单错误就近显示；批量部分失败列出成功和失败数量、失败对象及可用重试入口，不笼统提示成功。
- 弹窗包含标题、内容和固定顺序的操作区。普通表单建议宽 560px、复杂表单 800px，手机适配到可视宽度；内容区滚动时操作仍可达。
- 状态不能只靠颜色区分。`BUSY`、`READY`、初始化、重连、故障继续沿用既有容量口径，避免把“空载就绪”显示成“正在占用”。

### 6.3 草稿与保存边界

- 配置编辑保持“当前生效值、已保存值、编辑草稿”的区别，保存与重启是独立动作。
- 页面离开存在未保存草稿时提供继续编辑或放弃选择；如果提供保存选项，必须等待保存成功后再跳转。覆盖侧栏跳转、浏览器返回及刷新场景。
- 定时刷新不能覆盖草稿。保留版本冲突检测、放弃草稿、撤销待重启变更和隐藏字段保留行为。
- 账号登录配置、节点池设置各自保留保存边界，不能因控件样式统一而改成编辑即提交。
- 模型启用状态通过独立的“应用启用状态”操作提交；层级权限通过配置页保存。必须保留两者不同的作用范围、反馈和提交入口，不能误合并为一次保存。

## 7. 各页面改造方案

### 7.1 概览与调度

- 页首先显示服务状态、请求活跃数、排队数和浏览器池摘要；说明统计时间窗口和数据更新时间。
- 调度模式只显示适用指标，保留 legacy 与模型调度的差异提示；不展示无法获得的虚假零值。
- 将模型运行情况作为主要内容，账号 × 模型详情、冷却和故障诊断按需展开。
- 降低重复状态卡和大面积颜色的比重，日常操作与低频恢复操作分区。
- 保留模型隐藏、恢复账号、恢复模型及所有现有动作的作用范围与反馈。

### 7.2 账号管理

- 页头以“新增账号”为主操作；导入、导出、上传 Auth、VNC 登录组成清晰的次操作区或更多菜单。
- 登录队列展示紧凑摘要，运行任务和登录配置按需展开；配置草稿、暂停状态及清理故障提示仍清晰可见。
- 搜索、状态、层级、代理等现有筛选按统一工具栏排列；保留现有筛选能力，不凭空新增后端筛选。
- 表格优先展示身份、会话状态、账号层级、代理出口和任务状态。长邮箱允许换行或查看完整内容，敏感值不直接暴露。
- 行内保留常用操作，其余进入具备明确文字的更多菜单；批量操作显示选中数，并明确“当前页、已选账号、全部匹配”的区别。
- 保留跨页选择、筛选全选、导出范围、导入预览选择、运行中登录取消，以及层级来源、待复检和冲突提示。

### 7.3 节点池

- 分为运行状态、节点、订阅和绑定等已有功能区；Mihomo 路径、端口及测试地址放在设置区域，避免运行按钮与大量表单混排。
- 节点列表统一展示延迟、出口、绑定数与状态；直连、订阅缺失、未启用及未就绪分别表达。
- 添加节点为列表主操作，批量导入和测试为次操作；删除操作与测试、编辑保持视觉区分。
- 长地址、订阅 URL、节点名称及绑定账号在手机上可完整查看；不得因菜单折叠丢失测试、编辑、删除、绑定等入口。

### 7.4 系统配置

- 按现有配置定义分组，采用分组导航或锚点目录，避免一次展开所有复杂项。
- 保存区显示未保存项数、待重启项数，提供保存、放弃及独立重启入口。吸附操作区不遮挡正文和移动端键盘焦点。
- 常规项展示名称、说明、单位和生效方式；英文变量名通过说明入口查看，触屏同样可达。
- 模型权限矩阵、并发映射、资源分配、主控节点等复杂项保留完整编辑能力；折叠只是展示变化，不清除隐藏数据。
- API Key 和 Token 等字段保持遮蔽与显式修改语义；输入框空值是否保留凭证遵循现有接口，不统一做字符串清空。

### 7.5 用量统计与日志

- 用量页依次显示时间窗口、筛选、汇总和明细；统一成功率、耗时、数量和缺失值的格式。
- 保留自定义时间、分页、导入导出、存储保留期限提示及已有账号和模型细分维度。区分数据缺失与真实的零用量。
- 日志工具栏统一筛选、自动滚动及现有操作入口；日志区使用等宽字体，支持复制和明确的换行策略。
- 轮询更新不抢滚动位置；用户阅读历史时暂停自动跟随，恢复跟随后再滚至底部。日志游标及重置语义保持不变。

### 7.6 登录、VNC 与异常页

- 登录页沿用统一字体、表单、按钮及错误反馈；保留现有表单提交协议、字段名称和认证分支。
- VNC 保留适合远程画布的独立布局，只统一外围工具栏、连接提示、返回入口及弹层；不改动连接、缩放和人工操作机制。
- 404 和会话失效页使用共同的状态组件，返回路径明确。服务暂时不可用与登录过期分开处理。

## 8. 响应式与可访问性

| 宽度       | 布局规则                                                       |
| ---------- | -------------------------------------------------------------- |
| ≥ 1200px   | 完整文字侧栏，指标多列，表格优先                               |
| 768–1199px | 收窄或折叠侧栏，筛选自动换行，复杂详情减少并列列数             |
| < 768px    | 抽屉导航，标题与操作分行，指标双列或单列，主要列表使用适配布局 |

- 手机页面不出现整体横向溢出。权限矩阵和确需横向查看的表格可在独立容器滚动，并提供可发现的提示。
- 表格与移动卡片使用同一份选择和操作状态，不能分别维护导致选中丢失。
- 弹窗在小屏和软键盘出现时可滚动，取消和提交可达；长中文、英文和长 ID 均需检查。
- 键盘可完成导航、筛选、选中、提交和关闭弹窗。焦点可见，关闭弹窗后回到触发控件。
- 表单有可关联标签，状态和错误具有可访问名称；尊重减少动画设置。
- 验收宽度至少覆盖 360、390、768、1280、1440px，并覆盖 200% 缩放下的主要操作。

## 9. 代码组织与迁移策略

建议渐进形成以下结构，名称可随实际代码调整：

```text
ui/app/
  layouts/                    公共工作区框架
  components/common/          页头、区块、筛选、状态等共用组件
  components/icons/           本地 SVG 图标
  pages/                      各路由页面
  composables/                有明确生命周期的轮询及页面状态逻辑
  styles/
    variables.less            视觉变量唯一来源及旧变量兼容映射
    global.less               重置、字体、焦点和基础布局
    element-overrides.less    Element Plus 变量映射及必要覆盖
```

- 通过 CSS 变量把 Element Plus 的主色、字体、边框、圆角和控件尺寸映射到同一来源。先保留旧变量别名，迁完使用方再删除。
- 全局样式只定义跨页面约定；页面局部样式限定作用域，避免依赖 DOM 层级的大范围覆盖和不断追加 `!important`。
- `StatusPage.vue` 按页面边界逐步拆分。先保持现有请求和数据流，再抽公共逻辑，不同时重写调度数据模型。
- 明确每个轮询、事件监听和 AbortController 的所有者；路由卸载时清理。若采用页面缓存，必须处理激活与停用，避免后台重复请求。
- 全局业务请求不因拆成多个组件而各自重复轮询；页面离开和返回时保持现有即时刷新能力。
- 组件库迁移时校对原生表单的提交类型、文件上传、分页索引、数值类型、禁用条件及确认行为。

## 10. 分阶段实施与交付

| 阶段         | 工作内容                                               | 交付与进入下一阶段的条件                                          |
| ------------ | ------------------------------------------------------ | ----------------------------------------------------------------- |

## 11. 验证与验收

### 11.1 自动检查

根据实际修改运行相关检查；最终整体验收运行：

```bash
npm run lint
npm test
npm run build:ui
```

主要复用并按行为变化更新 `tests/accounts-page.test.js`、`tests/configuration-page.test.js`、`tests/realtime-dashboard.test.js`、`tests/proxy-pool.test.js` 及相关测试。先确认每个测试实际覆盖范围，不能仅凭文件名认定已完成界面验证。

新增测试聚焦路由直达和返回、草稿保护、跨页选择、刷新状态保留、移动操作可达及弹窗键盘行为。优先按角色、标签和稳定测试标识定位，不把旧 CSS 类名或静态 HTML 结构当作业务要求。

浏览器用例需要预先准备可用的 Playwright 浏览器。报告分别列出通过、失败和跳过，跳过不计为已验证。真实登录、VNC 和上游操作按现有验收要求单独验证，模拟接口测试不能替代。

### 11.2 验收清单

- [ ] 所有管理页使用统一导航、页头、字体、间距、颜色、图标与组件状态。

- [ ] 新旧路由可直达，刷新和前进后退正确，未登录访问仍遵循鉴权。

## 12. 实施决策与后续事项

首版采用浅色、单一蓝色强调色、Element Plus 基础控件、文字导航和紧凑布局。首个样板为账号页，涵盖表格、任务、筛选、批量操作和弹窗，足以检验统一规范是否可复用。

暗色主题、公开看板整体重做、复杂图表替换及后端接口扩展后续单独评估。本轮验收以管理端一致性和既有功能完整性为准。
