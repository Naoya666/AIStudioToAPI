# 账号层级、付费权益检测与 Argon 调度改造方案

日期：2026-10-18。状态：需求已确认，本文用于指导实现与验收，不代表功能已经完成。

## 1. 目标与范围

当前 Argon 采用 `ARGON_VERIFIED_ACCOUNTS` 人工白名单和当前页面 `ready-paid` 双重检查。新增账号可能来自账号密码自动登录、VNC 登录、Cookie/Auth 导入；统一在新增时打开浏览器检测会增加资源消耗，维护 authIndex 白名单也不方便。

本次改造以账号管理中的手动层级作为优先依据，独立保存上游权益检测结果，并支持管理员按需进行单个或批量检测。Argon 使用统一的本地层级准入；上游是否允许调用仍由真实认证、真实权益头及调用结果决定。

本次包括：

- 账号列表层级列、编辑凭据中的层级设置和只读权益结果。
- 单个、批量付费权限检测及有资源边界的检测队列。
- 自动保存正常运行中已经发生的权益查询结果。
- 替换 Argon 人工白名单及强制付费预检准入。
- 按账号层级估算各模型剩余额度。

本次不开发原生流式，不改变 MakerSuite 缓冲输出，不通过生成请求验证权益，不新增定时权益扫描，不因估算余额归零新增调度拦截。

## 2. 已确认的业务规则

### 2.1 三种状态独立保存

1. **手动层级**：管理员声明的套餐，允许修改和清除。
2. **检测结果**：上游实际返回的权益及检测时间，只读，不允许管理员写入或伪造。
3. **账号 × 模型状态**：实际调用产生的不支持、限流、冷却等状态，继续由调度器维护。

修改其中一种状态，不应顺带清除另外两种状态或历史用量。

### 2.2 手动层级与有效层级

手动层级支持：

| 存储值（建议） | 界面名称               | 含义                               |
| -------------- | ---------------------- | ---------------------------------- |
| `null`         | 未设置（跟随检测结果） | 没有人工声明，不能与 Free 合并保存 |
| `free`         | Free                   | 管理员明确指定免费层级             |
| `pro`          | Pro                    | 管理员明确指定 Pro                 |
| `ultra`        | Ultra 5x               | 管理员明确指定 Ultra 5x            |
| `ultra20`      | Ultra 20x              | 管理员明确指定 Ultra 20x           |

统一计算有效层级：

```text
手动层级非空 → 使用手动层级
否则，有当前有效的成功检测：
    ready-free → Free
    ready-paid + TIER1/TIER2 → Pro
否则 → 未知
```

TIER1/TIER2 仅在展示及本地额度策略中回退为 Pro，不推断 Ultra 5x 或 Ultra 20x。编辑凭据始终显示原始检测信息。

有效层级为未知时，其他已支持模型按 Free 额度估算，Argon 不准入。有效层级明确为 Free 时，Argon 同样不准入。

### 2.3 准入与冲突矩阵

| 手动层级                   | 当前有效检测                       | 列表展示 | Argon 本地准入 | 不一致提示 |
| -------------------------- | ---------------------------------- | -------- | -------------- | ---------- |
| 未设置                     | 无 / 失败且无成功结果 / 旧会话结果 | 未知     | 否             | 否         |
| 未设置                     | Free                               | Free     | 否             | 否         |
| 未设置                     | TIER1 或 TIER2                     | Pro      | 是             | 否         |
| Free                       | 任意                               | Free     | 否             | 否         |
| Pro / Ultra 5x / Ultra 20x | 无 / 查询失败 / 旧会话结果         | 手动层级 | 是             | 否         |
| Pro / Ultra 5x / Ultra 20x | TIER1 或 TIER2                     | 手动层级 | 是             | 否         |
| Pro / Ultra 5x / Ultra 20x | 明确 Free                          | 手动层级 | 是             | 是         |

“是”仅表示通过层级检查；账号仍需满足已有健康、会话、模型启用、冷却和并发条件。

冲突提示建议为：“手动设置为付费账号，但最近一次有效检测为 Free，请检查订阅或账号会话。”提示不阻止调度。手动 Free 与检测付费不提示冲突，也不自动升级。

## 3. 数据保存与生命周期

建议在现有账号数据库记录上增加字段，不另建依赖 authIndex 的白名单。账号身份使用稳定的账号 ID；authIndex 仅用于关联现有浏览器与调度器。

示意结构（字段名称可在实现时与现有规范统一）：

```json
{
  "manualTier": null,
  "benefitObservation": {
    "state": "ready-paid",
    "rawTier": "TIER1",
    "source": "query",
    "observedAt": 1792252800000,
    "sessionVersion": 12
  },
  "benefitLastCheck": {
    "status": "succeeded",
    "checkedAt": 1792252800000,
    "reason": null
  }
}
```

- Free 成功结果保存 `state=ready-free`，`rawTier=null`；界面明确显示 Free，不把 null 解释为未检测。
- `benefitObservation` 保存最近一次成功观察；最近检测失败只更新 `benefitLastCheck`，不覆盖成功结果。
- 来源区分主动查询、正常流程查询、原生请求头观察。原生头能证明当时捕获到的 TIER1/TIER2；缺少该头不能推断 Free。
- 查询状态与队列状态分离；排队或执行中不清除已有成功检测。
- 同一会话查询失败时，保留之前成功结果及时间，并展示最近检测失败。
- Cookie 替换、重新登录或会话版本更新后，旧观察保留为历史回显，标记“待复检”；不参与新会话的检测回退及冲突判断。手动层级继续有效。
- 账号删除后取消检测；迟到结果不可恢复已删除账号。旧会话、旧页面、旧浏览器实例的结果不可覆盖新会话。
- 支持密码登录、VNC、Cookie/Auth 导入账号；已有账号刷新认证时保留手动层级。新账号缺省为未设置，不自动变成 Free。
- 新增字段通过现有数据库保存路径持久化，兼容缺少这些字段的旧记录。普通 Cookie 下载不夹带管理员凭据或内部检测数据；如现有备份格式支持账号元数据，需明确其版本兼容策略。
- 编辑接口仅接受手动层级，不接受客户端写入原始权益结果、有效层级或冲突标记；这些字段由服务端计算。

## 4. 权益检测的触发方式

### 4.1 主动检测

账号操作栏新增“检测付费权限”。批量操作栏新增“批量检测付费权限”，沿用已有跨分页账号选择语义。

点击仅提交任务，HTTP 接口及时返回排队结果，不等待浏览器完成。检测只调用 `GetAiStudioBenefitTier`，不发送 `GenerateContent`、不发测试提示词，不通过任何模型生成来取得认证或验证权限。

查询前可以完成正常页面加载并观察页面原生认证。如果在有界时间内无法获取认证，返回明确失败或未登录结果，不触发自动登录、自动恢复或生成请求来补救。

`GetAiStudioBenefitTier` 是独立权益 RPC，当前调用正文为 `[]`，不包含模型与提示词。本项目不将它计入模型请求数、token 或额度消耗。未找到该内部接口公开的计费或限流承诺，因此不在界面承诺“绝对无任何上游限流”，也不将页面普通网络请求算作模型生成。

### 4.2 正常运行中的同步

- 正常流程已经调用权益接口时，保存成功结果及失败状态。
- 原生请求已携带真实 TIER1/TIER2 时，可以同步为原生权益观察。
- 不为了同步层级额外调用权益接口。
- 不在账号新增、导入、登录成功、轮换、首次 Argon 请求或页面初始化时新增强制权益查询。
- 取消现有仅因白名单或 Argon 请求触发的强制 `ensure()` / `assertReady()` 查询。
- 桥接已有认证获取及真实权益头捕获继续保留；没有缓存权益时不伪造、不通过额外查询阻塞本地已准入请求，上游响应决定实际结果。

## 5. 检测队列与浏览器资源边界

### 5.1 容量规则

- 检测队列全局执行并发为 1，批量任务按账号串行推进。
- 优先复用该账号已有且可安全使用的上下文，不导航或干扰正在生成的页面。
- 同账号正在生成、登录或恢复时等待资源，不并行开启该账号的第二份活动会话；等待必须有界，可取消。
- 没有可复用上下文时，普通容量允许则按现有容量管理创建临时上下文。
- 普通容量已满时，允许最多额外创建 **1 个全局检测专用 context**。此例外跨单次和批量检测共享，不能每个账号各超额创建一个。
- 检测专用 context 不进入普通生成调度候选，不承接业务请求，不计作普通预热池目标。
- 跨账号检测应关闭旧临时 context，再使用下一账号的独立 storage state 创建新的 context，禁止在同一个活动 context 中直接混用不同账号认证。
- 临时 context 用完及时释放；复用的普通 context 不由检测服务销毁。
- 临时检测页面安装观察器时不得误通知普通调度器，使其把临时检测状态当作普通池上下文状态。

### 5.2 任务管理

任务状态至少包括：排队、等待账号空闲、检测中、成功、失败、已取消。

- 同账号待执行及执行中的任务去重，重复提交返回已有任务。
- 批量提交逐账号反馈成功入队、重复、无法检测等结果；无认证的账号不自动登录。
- 提供批量进度、逐账号结果、取消等待任务及取消当前检测能力。
- 单个账号失败不终止整批；页面创建、认证等待、查询、资源等待均设置有界超时。
- 取消、超时、账号删除、会话更新、浏览器重启、服务退出后均释放临时资源和队列占用。
- 进程重启后，原执行中任务标记中断，不能显示为永久执行中；不自动恢复批量检测以启动浏览器。
- 队列容量有上限，批量输入校验、认证、鉴权和去重不能被绕过。

可以借鉴自动恢复队列的交互和任务管理方式，但检测任务不能被注册成自动恢复任务，也不触发自动登录。

## 6. Argon 调度与真实权益头

### 6.1 统一层级判断

新增共享层级解析模块（建议 `src/accounts/AccountTierPolicy.js`），集中计算有效层级、来源、Argon 准入、冲突和每模型额度。列表、快照、调度器和桥接不得分别实现不同优先级。

替换以下旧条件：

- `ARGON_VERIFIED_ACCOUNTS` 是否包含 authIndex。
- Argon 必须已有当前页 `ready-paid` 才允许租用或发送。
- 为满足以上条件自动触发权益预检。

页面是否属于当前账号和会话、文档是否已销毁、请求注册与认证是否有效等检查继续保留。

旧 `ARGON_VERIFIED_ACCOUNTS` 不再授予或限制资格，不转换为人工 Pro。配置项应废弃并更新文档；旧环境变量可以兼容读取但仅提示已废弃，不能影响新规则或导致启动失败。

### 6.2 请求头与错误处理

- 手动层级只决定本地准入与额度策略，不写入或伪造 `x-aistudio-g1-tier`、扩展权益头、认证或 Cookie。
- 请求使用当前页面实际捕获到的有效权益；客户端提交的权益头不能作为账号权益证明。
- 手动付费、检测 Free 时继续允许真实请求，由 Google 决定是否接受。
- 检测 Free 不设置 `unsupported`，检测成功不清除已有 `unsupported`。
- 实际模型权限错误继续按当前账号 × 模型规则禁用；“恢复模型”清除该调用状态，允许再次尝试，层级准入条件仍然有效。
- 429 沿用真实限流及冷却，不按权限错误处理；认证过期、桥接认证失败、查询失败仍保持原有错误类别。
- 本次不扩大“权限错误”的匹配范围，不因任何失败都永久标记无权限，不新增自动生成重试。
- 修改手动层级、重新检测和恢复模型均不清除历史统计或当日尝试数。
- legacy 调度及模型传输覆盖同样使用统一层级准入，不能仅修改新调度器而留下发送前旧门槛。

## 7. 分层额度预估

采用参考项目的分层基数作为本地预估策略，不宣称为上游实时余额：

| 有效层级    | 每个 Flash 模型 | 每个 Pro 模型 |     Gemini 4 Argon |
| ----------- | --------------: | ------------: | -----------------: |
| 未知 / Free |             100 |            10 | 不准入，不贡献额度 |
| Pro         |             100 |            50 |                 50 |
| Ultra 5x    |             500 |           100 |                100 |
| Ultra 20x   |             500 |           200 |                200 |

- “未知”仅对普通模型采用 Free 基数，不能据此给 Argon 分配免费额度。
- 精确识别 `gemini-4-argon`，不自动放行其他 `gemini-4-*`；沿用已有模型规范化和别名处理。
- 额度按账号、具体模型独立计算，不把所有 Pro 模型或 Argon 的请求共用一个桶。
- 每个账号模型预估剩余为 `max(0, 当前层级基数 - 当日上游尝试数)`，沿用失败尝试计数语义。
- 聚合使用每个账号各自的层级基数；Argon 只汇总层级准入账号，不能以全部账号数乘 50。
- 沿用现有有效轮换账号集合；账号健康、冷却、模型隔离等可调用状态与本地剩余估算分别展示，不将剩余额度解释为当前可立即调用次数。
- 普通模型未知上限仍保持不可估算，不扩展到 embedding、imagen 等未定义模型。
- 修改层级只改变基数，不重置已用次数；因此剩余估算可能随层级升降而变化。
- 不因预估归零新增本地拒绝；真实 429 和现有冷却仍参与调度。
- 管理调度页、公开看板、聚合看板及汇总字段使用相同计算口径。混合层级不再展示误导性的统一“账号数 × 单账号额度”，应展示总基数或分层明细。

本轮保留项目当前 `America/Los_Angeles` 自然日统计口径，不直接照搬参考项目固定北京时间 15:00 日切。真实内部通道重置时间缺少充分证据，调整日切规则需独立验证，不与层级改造混合。

## 8. 前端交互

### 8.1 账号列表

在账号与会话/恢复之间增加“账号层级”列：

- 主标签显示 Free / Pro / Ultra 5x / Ultra 20x / 未知。
- 附带手动或检测来源；旧检测结果标记待复检。
- 仅规定的付费对 Free 冲突展示提醒，不阻断操作。
- 操作栏增加“检测付费权限”；当前账号正在检测时显示进度或已有任务状态，避免重复点击。
- 批量栏支持对当前选择集检测和取消，选择行为与已有批量操作一致。
- 窄屏维持现有响应式交互，不因新增列隐藏恢复或编辑入口。

### 8.2 编辑凭据

- 手动层级下拉框，包含“未设置（跟随检测结果）”。
- 独立只读区域显示：原始权益（Free / TIER1 / TIER2 / 未检测）、来源、成功观察时间、是否属于当前会话、最近检测状态与失败原因。
- 显示当前有效层级及冲突说明，避免把 TIER1/TIER2 误标成精确套餐。
- 清除手动选择后立即按检测回退规则计算；检测区域不可编辑。
- 不因修改层级要求重新提交密码，不改变已有凭据的保留和清除语义。

## 10. 验收标准

### 10.1 层级与数据

- 覆盖未设置、Free、三个付费档和全部检测状态的优先级矩阵。
- 未设置与 Free 可独立持久化；旧账号默认未设置，普通模型额度与原 Free 基数一致。
- 三种新增入口不自动触发权益检测或额外启动浏览器。
- 重启、Cookie 刷新、重新登录、删除、去重合并后不出现层级串号或迟到覆盖；合并时不同人工层级不能静默丢失，需保留可审阅的冲突处理。
- 只读检测结果无法经编辑接口写入。

### 10.2 检测资源与行为

- 单个及批量检测只发权益 RPC，验证没有模型生成请求、没有模型用量计数增加。
- 复用空闲上下文不破坏普通请求；忙碌账号等待。
- 普通容量满时，无论多少批次最多额外一个检测 context，且不进入生成池。
- 同账号重复提交去重；取消、超时、页面失败、浏览器重启和进程退出均能结束任务并释放资源。
- 查询失败保留原成功结果；新会话不使用旧结果授予资格。
- 正常流程已有查询被同步，但没有为了同步新增查询。

### 10.3 调度与真实权益

- 手动 Pro + 检测 Free：提示冲突，本地允许尝试，出站头不伪造。
- 手动 Free + 检测付费：本地拒绝 Argon，不提示规定范围之外的冲突。
- 未设置 + 当前 TIER1/TIER2：按 Pro 准入；未设置且未知/Free：Argon 不准入。
- 检测本身不隔离或恢复模型；实际权限错误隔离后可在账号 × 模型界面恢复。
- 429、认证失效、桥接认证失败、历史统计、请求重试和缓冲输出语义不回归。
- 调度及非调度发送路径都不再依赖旧白名单或强制 ready-paid。

### 10.4 额度与界面

- 混合 Free/Pro/Ultra 账号按分层基数逐账号汇总；Argon 不给免费/未知账号贡献额度。
- 升降级不清计数；别名归一、太平洋日切、失败尝试扣减及未知模型行为一致。
- 预估归零本身不新增阻断，后台和公开看板口径一致。
- 单个/批量交互、跨分页选择、编辑只读字段、冲突提醒和移动端均可操作。

建议使用本地 fixture 覆盖权益 RPC、队列和资源边界；真实账号验收以管理员主动检测为入口，不自动生成测试内容。真实 Argon 生成验证使用正常业务请求或另行明确安排，不作为本轮检测按钮的隐含行为。
