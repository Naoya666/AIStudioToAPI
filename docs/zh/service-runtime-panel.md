# 后台服务运行情况

后台概览的“服务运行情况”展示当前应用实例的数据，保持现有单容器部署，无需 Docker socket 或容器管理权限。

- 主服务：进程状态、PID、运行时长和 Node RSS。运行时长在应用进程重启后重新计时。
- 调用后端：根据 `CALL_BACKEND` 展示浏览器或本地引擎的连接状态；正在恢复、初始化超时和上下文尚未就绪分别展示对应状态。恢复次数来自浏览器管理器，本地引擎自动重启次数单独展示。
- 调度器：展示持有执行租约的工作槽数量和排队数。传统模式显示“传统模式”，不虚构独立调度服务。
- 上下文池：展示就绪、初始化中和初始化超时数量。

Node RSS 只包含当前主服务进程。部署资源组内存读取当前进程所属 cgroup 的整体用量，包含同组浏览器和其他子进程，不应与 RSS 相加。支持 Linux cgroup v1/v2，通过 `/proc/self/cgroup` 和 `/proc/self/mountinfo` 定位实际资源组。非 Docker 部署时该指标表示进程所属资源组，并非固定表示一个容器。上限表示当前资源组自身配置的上限；父级资源组仍可能施加额外约束。无法读取用量时显示“暂不可用”；无法读取上限时不会当作未设置上限，也不会拿宿主机总内存替代。

数据随概览刷新，通过已登录会话访问 `GET /api/status/runtime`，响应禁止缓存。刷新失败会隐藏旧运行数据并停用重启按钮。

“重启应用”复用现有配置重启接口和进程监督器，整体重启应用及其管理的后端，不提供模块级独立重启。确认提示说明全部已保存配置会被加载，包括待生效项；未保存草稿不会应用，未完成请求可能中断。界面核对新实例 ID、就绪状态、运行配置版本和待生效项后才报告成功。未启用监督器时禁用按钮，重启失败或无法在六分钟内确认时展示错误。

验证命令：

```bash
node --test tests/runtime-status.test.js tests/configuration-restart.test.js
npm run test:browser:runtime
npm run build:ui
```

浏览器验证使用模拟状态和重启响应，不会重启实际应用。
