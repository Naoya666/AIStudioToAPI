# 账号管理独立分页与自动登录、会话恢复改造方案

> 后续实现已引入可选的独立登录浏览器跨任务复用，每次尝试仍创建独立 Context。涉及执行器生命周期的现行补充方案见 [浏览器复用优化方案](account-login-browser-reuse-plan.md)。

## 1. 背景与目标

公益站账号池主要由约 150 个 Workspace 子账号组成。根据当前运营观察，这些账号的浏览器会话约两周后会失效。目前项目检测到跳转 Google 登录页面后，将认证文件标记为过期并移出轮询，管理员需要手动重新获取 Cookie，维护成本较高。

本次改造建立统一的自动登录流程：管理员提供邮箱、密码及可选的验证器密钥，系统完成登录、验证 AI Studio 可用性、保存浏览器会话；已有账号会话过期后，使用已保存凭据自动恢复。不能自动处理的验证要求进入人工处理状态，并提供按需查看的失败截图与日志。

本文是实施需求与设计约束，所列新增组件、接口和配置尚未实现。约两周的有效期是运营现象，不作为固定的过期计算规则。

## 2. 已确认的要求

1. 将首页底部的“账号管理”迁移为独立的“账号管理”分页，保留原有功能。
2. 新增邮箱、密码、可选验证器密钥登录方式；兼容无二步验证和验证器 TOTP 登录。新增账号与过期恢复共用登录引擎。
3. 登录使用独立后台队列，与处理 API 请求的浏览器队列分离。默认并发为 **1**，支持配置并发，并保证超时不会堵死队列。
4. Cookie 过期后立即停止调度该账号，后台尝试恢复；临时故障默认最多尝试 3 次，无法恢复时保留最后一次失败截图。
5. 保存密码和可选验证器密钥，允许管理员查看、编辑；现有只有 Cookie 的账号继续兼容。
6. **不增加额外鉴权**：沿用现有控制台登录会话和服务端鉴权，不增加角色系统、二次密码或额外身份验证。新增接口不能变为匿名接口。
7. 失败图片仅在点击“显示”或“查看”后请求，保留 7 天。
8. 支持 Google Authenticator 的 `otpauth-migration://offline?data=...` 导入并匹配账号。
9. 保留 VNC 人工登录，用于自动流程不能完成的验证。

## 4. 账号与任务数据模型

### 4.1 账号标识与凭据

为账号生成稳定的 `accountId`，通过 `authIndex` 关联现有 `configs/auth/auth-{index}.json`。新增账号登录失败时也有账号记录，但 `authIndex` 可以为空。

账号至少包含：

- `accountId`、`authIndex`、显示名称和真实登录邮箱；邮箱匹配键使用去除首尾空白并转为小写的完整邮箱。
- 密码、可选的 TOTP 密钥及必要参数、`credentialVersion`。
- 会话状态、恢复状态、是否启用自动恢复。
- 最近成功登录时间、最近过期时间、最近失败分类、当前任务 ID 和下次尝试时间。

人工禁用状态以现有调度器为准，不在凭据存储中再建立一个独立的权威禁用字段。健康会话、自动恢复开关与人工禁用是不同概念。

凭据使用独立的本地持久化存储，建议独立 SQLite 文件，避免扩展认证 JSON 时把账密混入现有下载或上传路径。数据库操作不得阻塞请求主线程，连接和写入队列应有明确上限。运行目录和截图目录需要挂载持久卷，文件权限限制为服务运行用户可读写。

凭据必须能被后台任务读取使用，不能仅保存密码哈希。首版采用受限本地存储，不引入额外解锁步骤；磁盘加密可作为独立后续增强，不作为本次交付依赖。

账号删除、Cookie 替换、重复邮箱去重和 VNC 保存都应通过统一服务维护关联关系。不能只靠可能重用的文件编号绑定凭据；账号删除后，旧任务不能向同编号的新账号写入数据。

### 4.2 状态口径

| 维度 | 状态                  | 含义                                   |
| ---- | --------------------- | -------------------------------------- |
| 会话 | `missing`             | 新账号尚无已验证的浏览器会话           |
| 会话 | `valid`               | 已验证会话，可在其他调度条件满足时使用 |
| 会话 | `expired`             | 当前会话不可用，立即退出请求调度       |
| 恢复 | `idle`                | 当前无恢复任务                         |
| 恢复 | `credentials_missing` | 缺少密码或实际登录所需的验证凭据       |
| 恢复 | `queued`              | 等待独立登录队列                       |
| 恢复 | `running`             | 正在登录或验证目标服务                 |
| 恢复 | `retry_wait`          | 临时故障后等待重试                     |
| 恢复 | `manual_required`     | 明确的人工验证要求或自动恢复次数耗尽   |

Cookie 过期不等同于账号封禁；“三次失败”也不能推断为封禁。界面显示实际失败原因，不使用无证据的“账号被封”结论。

任务另有 `succeeded`、`failed`、`cancelled`、`interrupted` 等终态。账号最近一次恢复结果由任务记录表达，避免把已结束任务仍显示为排队或运行。

### 4.3 任务与尝试记录

每个任务记录 `taskId`、账号 ID、来源（新增/过期/手动）、凭据版本、会话版本、创建时间、执行期限、当前阶段、尝试次数、下次执行时间和最终结果。

每次尝试记录开始/结束时间、阶段、耗时、错误分类、经过脱敏的错误信息、截图 ID 与截图生成结果。任务参数只引用账号凭据，不在队列和历史日志中复制密码或密钥。

## 5. 独立登录队列与防堵塞机制

### 5.1 隔离与调度

- 建立独立登录队列与执行器，不复用 API 请求调度队列、请求浏览器池容量、Context 初始化队列或全局请求恢复锁。
- 默认并发为 1；并发配置为正整数。调小并发不强行终止已有任务，等待运行数量下降后再启动新任务。
- 登录浏览器使用独立进程和独立 Context。建议每次尝试由独立子进程执行，管理进程负责调度、期限和回收，便于浏览器调用卡住时强制终止。
- 登录流程不依赖 VNC 的共享显示端口、会话锁或单会话资源；如需有界面环境，应提供独立资源。
- 队列任务持久化，前端收到 `202 Accepted` 和任务 ID 后结束请求。刷新页面、关闭页面不会停止任务。
- 默认 FIFO，重试任务到达 `nextAttemptAt` 才进入就绪队列；退避等待不占用并发槽，不阻塞其他账号。
- 提供暂停自动启动、恢复、取消和手动重试。暂停默认只停止启动新尝试，运行中的尝试继续；取消任务执行有界资源清理。
- 同一账号最多有一个未结束任务。多个过期事件或重复点击返回现有任务 ID，不重复排队。手动重试建立新任务，不重置旧任务的历史记录。
- 默认队列最多 1000 个未结束任务，包含排队、重试等待和运行任务；满队列返回明确结果，不能阻塞 API 请求等待空位。自动过期事件先持久化待恢复状态，由后台扫描在容量允许时补入，避免事件丢失。

独立队列仍与请求服务共享服务器 CPU、内存和网络，不能承诺完全没有资源影响。实现需限制登录进程数量，并避免后台登录触发请求浏览器池整体重启。

### 5.2 时间边界

建议默认值如下，均可配置；超时和日志时间使用 UTC，运行中的耗时控制使用单调时钟。

| 项目           | 默认值        | 起算点与语义                                          |
| -------------- | ------------- | ----------------------------------------------------- |
| 登录并发       | 1             | 同时执行的登录尝试数量                                |
| 单步超时       | 30 秒         | 每个页面操作，且不能超过本次剩余总时长                |
| 单次登录总超时 | 180 秒        | 获得并发槽后开始，含启动浏览器、登录和 AI Studio 验证 |
| 整轮恢复期限   | 15 分钟       | 第一次尝试开始时起算，含重试等待；初次排队不计入      |
| 最大尝试次数   | 3             | 包含第一次尝试，不是首次后再重试三次                  |
| 重试等待       | 30 秒、120 秒 | 两次重试增加等待，并加入少量随机抖动                  |
| 失败截图超时   | 5 秒          | 失败或总超时后，尽力采集证据                          |
| 资源清理超时   | 10 秒         | 截图之后的关闭和进程终止预算                          |
| 队列监控间隔   | 5 秒          | 独立执行器状态、超时和异常退出检查                    |

单次执行截止后立即撤销任务写入权限，最多再使用截图与清理预算，不得继续登录。整轮期限到达后停止新尝试并终止当前尝试，允许有界诊断与清理。重试若不能在剩余期限内合理执行，应结束任务并记录恢复期限耗尽。

### 5.3 超时必须终止底层工作

仅使用 `Promise.race()` 返回超时不能满足要求，因为底层浏览器调用可能仍然运行。

必须实现：

1. 管理进程维护每次尝试的期限与唯一执行令牌；超时、取消或异常退出立即使令牌失效。
2. 合作式取消通过取消信号传递，终止后禁止开始后续步骤。
3. 截图使用独立短超时，失败时记录“截图超时/页面已关闭”，继续清理。
4. 关闭 Page、Context 和浏览器，超出清理预算后终止该尝试所属的子进程及浏览器进程树。不能杀死请求浏览器、VNC 或其他任务的进程。
5. 控制进程确认执行器退出，或已完成安全的进程隔离与终止后，才释放执行槽。失败分支和异常退出都必须进入统一清理路径。
6. 若无法确认资源终止，将对应执行槽标为故障并告警，不可盲目释放后无限启动新浏览器。其余健康槽继续运行；受监督的登录执行器应能被重建。默认并发 1 的情况下，也应能通过终止并重建独立执行器恢复服务，无需重启请求服务。
7. 迟到的成功回调、重复 IPC 消息与旧执行器返回值必须拒绝。凭据版本、会话版本、账号存在性及令牌校验应在提交前和原子提交边界执行。

管理进程使用退出事件与期限监控，不依赖执行器主动报告失败；执行器心跳只用于诊断，不能延长绝对期限。

### 5.4 重启与退出

启动时将上次进程遗留的运行任务识别为 `interrupted`，检查账号、版本、尝试次数和恢复期限后，决定重新排队或转人工处理。保留已消费的尝试次数，不能因重启无限重试。首次尚未运行的排队任务保持排队。

退出时停止启动新任务，有界取消运行任务并清理执行器，保存可恢复状态。持久化失败时明确报错，不向前端声明任务已可靠创建。实现多实例部署时需增加跨实例领取租约和互斥；本方案首版按单个管理服务实例运行，不允许多个实例同时消费同一个队列存储。

## 6. 统一自动登录流程

1. 校验邮箱、密码和可选验证器密钥，创建账号记录或更新凭据，进入登录队列。
2. 领取任务，固定本次凭据版本，解析账号代理出口，创建独立浏览器环境。
3. 使用允许的 Google 登录入口，输入邮箱和密码，以页面状态驱动流程，不依赖固定等待时间。
4. 未要求二步验证时直接进入后续验证；出现可选择的验证方式且已配置密钥时，选择验证器输入流程。
5. 如要求 TOTP，在输入前即时生成验证码；剩余有效时间不足时等待下一个时间窗口。等待也计入总超时。
6. 页面明确提示验证码错误或过期时，允许下一时间窗口生成新码后再提交，默认每次登录最多额外提交一次；不能重复使用旧码或在响应未完成时连续提交。
7. 进入 AI Studio，确认实际登录邮箱与目标账号一致，并验证必要的服务加载与初始化条件。
8. 提交完整 `storageState`，更新已有认证文件或为新账号分配索引，刷新认证源，结束任务。

成功判定不能仅依据“离开登录页面”“获取到 Cookie”或“网页标题正常”。验证条件应复用现有目标服务的必要初始化判断，并给出明确失败分类；不需要为验证账号消耗一次模型生成请求。

选择器应兼容常见中英文登录页面，通过语义元素和页面特征识别状态，避免只用易变的 DOM 层级。未知页面进入可诊断失败，不无限点击或等待。

TOTP 默认支持 Google 常见的 SHA-1、6 位、30 秒周期；解析并保存输入参数，对不支持的算法、位数或 HOTP 类型明确拒绝，不静默改为默认值。使用维护中的 TOTP 库并以标准测试向量验证。部署说明包含服务器时间同步要求。

## 7. 失败分类与自动恢复

| 失败原因                                             | 行为                                                                |
| ---------------------------------------------------- | ------------------------------------------------------------------- |
| 网络超时、连接中断、临时页面加载失败、浏览器异常退出 | 在次数和期限内退避重试                                              |
| 验证码过期或明确的验证码错误                         | 按第 6 节进行有限的新码提交；仍失败则保留原因，转人工核对密钥和时间 |
| 密码错误、账号不存在、明确的账号停用提示             | 立即转人工，不重复提交相同账密                                      |
| 必须手机号验证、短信、设备确认、恢复邮箱、验证码图片 | 立即转人工，可使用 VNC 后续处理                                     |
| 页面要求验证器但未提供密钥                           | 标记缺少验证凭据，不假定账号未启用二步验证                          |
| Workspace SSO、强制改密码、条款或无法自动处理的挑战  | 转人工处理并记录页面阶段                                            |
| 账号代理配置失效、目标服务地区限制、持久拒绝访问     | 记录配置或可用性原因，停止相同条件下的盲目重试                      |
| 未知页面状态、超过恢复次数或期限                     | 转人工，保留最后一次失败证据                                        |

检测到 Cookie 过期时：

1. 继续保存现有 `expired: true` 并移出轮询，阻止新的请求使用该账号。
2. 检查自动恢复开关、密码是否存在、人工禁用状态和已有任务，决定排队、返回已有任务或记录等待补录。
3. 恢复在后台执行，当前 API 请求仍按现有故障恢复策略处理，不等待账密登录。
4. 缺少凭据时保持现有手动更新 Cookie 的处理方式；补录后允许点击“重新登录”。
5. 成功后按第 8 节提交会话，更新界面状态；失败不清除旧的过期标记。

人工禁用账号不自动排队。管理员可显式执行登录以更新其会话，但登录成功仍保持禁用；启用账号必须使用原有的恢复操作。

## 8. 会话提交、并发写入与兼容

认证文件继续保持现有 `cookies`、`origins`、`accountName` 等结构，不保存密码或 TOTP 密钥。自动恢复应更新原账号认证文件，新账号才分配新编号。

会话提交由管理进程统一执行，执行器只返回待验证或待提交的数据。提交前检查任务令牌、账号 ID、凭据版本、会话版本、删除状态及最新人工禁用状态。

现有 `_updateAuthFile()`、VNC 保存、文件上传、过期标记、手动恢复与自动登录提交使用统一的账号写入互斥和版本校验，避免旧 Context 将新会话覆盖、旧过期事件将新会话再次标为过期。认证文件采用同目录临时文件加原子替换，保留应保留的元数据。

在提交新会话之前使旧 Context 的会话写入权限失效，并按现有机制停止其调度、排空或清理失效请求与 Context。不能为更新一个账号重建整个请求浏览器池。

文件与数据库无法直接共享一个事务，需记录可恢复的提交阶段或提交日志：只有文件写入、认证源刷新和必要状态更新完成，才显示成功并恢复调度。进程在阶段中间退出时，下次启动按日志完成或回滚关联状态，避免数据库显示成功但文件仍过期。

账号恢复成功不等于重置全部模型状态。保留人工禁用、模型限流和独立的健康控制规则；因旧会话导致的 Context 不可用状态需要定向解除。

账号删除或修改邮箱、密码、密钥，以及手动上传新 Cookie，应使冲突任务失效。删除需先阻止旧任务提交，再清理账号记录和关联资源。去重时优先保留有效会话，凭据相同可合并；凭据冲突须展示并让管理员选择，不能静默覆盖。

## 9. 独立账号管理页面

新增 `/accounts` 页面，名称“账号管理”，控制台导航可直接进入。首页可保留账号数量摘要和入口，移除原完整管理区。

保留现有列表、搜索、仅过期筛选、单个/批量上传、单个/批量下载、单个/批量删除、去重、切换账号以及 VNC 登录功能。现有 `/auth` 入口保持兼容，可从账号管理页进入。

新增功能：

- 新增账号：填写邮箱、密码、可选密钥，提交后展示任务状态。
- 查看/编辑凭据：默认遮罩，点击“显示”才读取密码和密钥；保存后可选择立即重新登录。
- 凭据字段未传表示不修改；空字符串不隐式清除。使用明确的清除操作区分“不修改”与“删除凭据”。
- 每账号自动恢复开关、手动重新登录、取消任务、失败截图和日志查看。
- 队列面板：并发设置、运行/排队/退避数量、当前阶段、执行时长、暂停/恢复及故障槽状态。
- 筛选：缺少凭据、过期、排队、登录中、等待重试、需要人工处理。
- 分页、批量选择及账密导入，适配 150 个账号维护。

列表只返回 `hasPassword`、`hasTotpSecret` 等配置标志，不返回凭据正文。队列状态轮询或事件推送只发送元数据，不携带截图。登录任务失败时，前端显示错误分类、失败阶段和下一步可采取的操作。

## 10. 批量账密与验证器导入

### 10.1 账密 CSV

支持 UTF-8 CSV，列为 `email,password,totpSecret`，其中 `totpSecret` 可选。正确处理 CSV 引号、逗号、换行和 BOM，不裁剪或改变密码内容。

导入先解析并展示匹配预览，再由管理员提交。预览不显示密码或密钥正文。匹配现有账号时仅按完整邮箱匹配；不存在的邮箱可明确选择创建账号记录，默认不立即批量发起登录。重复行、空密码、无效邮箱和冲突应单独列出。

预览提交需校验账号及凭据版本，发现期间发生修改时拒绝相关行并重新预览。导入结果展示新增、更新、跳过与失败数量及原因，部分失败不伪报整批成功。

### 10.2 Google Authenticator 迁移链接

支持粘贴多条 `otpauth-migration://offline?data=...` 链接或上传包含这些链接的文本文件；同时支持普通 Base32 密钥和 `otpauth://totp/...`。首版不要求二维码图片识别。

解析迁移链接时严格解析 URL、解码 `data` 的 Base64 与 Protobuf 数据，提取密钥、名称、发行者、算法、位数、类型及批次字段。处理 URL 编码与 Base64 中的 `+`，不能把合法字符错误转换为空格。

同一次导入识别批次 ID、批次总数和批次序号，重复批次去重，缺失批次明确提示。默认完整批次才能提交；如支持部分导入，须由管理员显式选择，且不能宣称完整导入。

匹配规则：

1. 从名称或带发行者前缀的名称提取完整邮箱，使用规范化邮箱做精确匹配。
2. 不根据数字编号、邮箱局部相似或显示顺序推断关联。
3. 未找到账号、多个候选账号、无邮箱条目提供手动映射或跳过。
4. 已存在相同密钥的条目幂等跳过；已有不同密钥必须在预览中显式选择覆盖。
5. 无效密钥、不支持的参数或类型、损坏数据明确拒绝；不自动创建未知账号或修改二步验证设置。

迁移格式需通过格式定义和脱敏固定样例验证。原始上传内容只用于处理，不写入常规日志，不长期保存，不在文档或测试中加入真实密钥。导入请求设置合理的大小与条目上限，建议默认 1 MiB、1000 条。

## 11. 失败截图、日志与清理

自动登录失败与超时均尽力截图，每次失败尝试最多一张，账号界面默认查看最后一次失败的图片。超时或页面已关闭导致无截图时，仍记录结构化日志并显示截图不可用原因。

截图由独立 `LoginArtifactService` 管理，使用任务与截图 ID 定位，不接受前端传入任意文件路径。不直接复用当前写入项目根目录的通用调试截图机制。

- 图片存放独立持久目录，生成时间起保留 7 天，启动时及每小时清理过期文件和元数据。
- 每账号最多保留 10 张失败截图，超出删除最旧图片；删除图片不会删除该次尝试的结构化记录。
- 前端必须点击“显示/查看”才请求图片；不得在列表中返回 Base64 图片、自动预加载缩略图或后台下载。
- 查看接口沿用控制台鉴权，返回 `Cache-Control: no-store`。关闭预览或切换账号后释放前端对象 URL。
- 清理后的截图返回 `410 Gone`，从未生成的截图显示“未生成”及原因。存储错误单独显示，不能混淆为已过期。
- 拍摄前尽力遮罩密码、密钥与验证码输入框；禁止保存含凭据的完整 HTML、浏览器 Trace、请求正文或原始迁移链接。

日志记录任务 ID、账号 ID、尝试次数、阶段、错误分类、耗时及经过脱敏的页面路径。不能记录密码、密钥、验证码、完整 Cookies 或带敏感查询参数的完整 URL。

结构化任务与尝试历史默认保留 30 天，可配置；未结束任务不因历史清理删除。账号保留最近一次失败摘要，截图到期后摘要仍可用于定位问题。

## 12. 接口建议与访问约束

以下为新接口建议，实施时与现有 `/api/accounts/current`、`batch`、`deduplicate` 等静态路径协调，静态路径先注册，并避免动态参数捕获已有接口。

| 接口                                                     | 用途                               |
| -------------------------------------------------------- | ---------------------------------- |
| `GET /api/account-management/accounts`                   | 账号列表和状态，不含凭据与图片正文 |
| `POST /api/account-management/accounts`                  | 创建账号并提交登录任务             |
| `GET /api/account-management/accounts/:id/credentials`   | 点击显示后读取凭据                 |
| `PATCH /api/account-management/accounts/:id/credentials` | 编辑/清除凭据和自动恢复开关        |
| `POST /api/account-management/accounts/:id/login`        | 手动排队，同账号任务去重           |
| `GET /api/account-management/login-tasks`                | 分页查询任务和日志元数据           |
| `POST /api/account-management/login-tasks/:id/cancel`    | 取消任务并启动有界清理             |
| `GET /api/account-management/login-queue`                | 队列状态与配置                     |
| `PATCH /api/account-management/login-queue`              | 并发与暂停状态设置                 |
| `POST /api/account-management/import/preview`            | 账密 CSV 或验证器导入预览          |
| `POST /api/account-management/import/commit`             | 提交已校验的映射和覆盖选择         |
| `GET /api/account-management/artifacts/:id`              | 点击后读取失败图片                 |

上述接口全部复用现有 `isAuthenticated`。凭据响应不缓存，不能在接口异常中回显请求账密。导入预览结果与当前控制台会话关联，使用有期限的预览 ID；重复提交保证幂等，不在前端预览结果中包含秘密。

任务创建成功返回 `202` 和任务 ID；参数错误返回 `400`；版本或账号冲突返回 `409`；队列容量不足返回 `429` 并提供稍后重试提示；服务或持久化不可用返回 `503`。原有接口行为保持兼容，确需调整时同步修改前端和测试。

## 14. 迁移与实施顺序

1. 抽取独立账号管理页面，保留现有所有操作与服务端鉴权，确保路由直达可用。
2. 实现账号存储和稳定 ID，为现有认证文件建立关联；缺少真实邮箱的记录标为待补录，不猜测邮箱。
3. 实现凭据编辑、CSV 和验证器导入。现有 Cookie 不改写、不要求重新登录，不删除重复记录。
4. 实现独立队列、执行器、总超时、取消、资源回收、持久化及截图清理，再接入浏览器登录引擎。
5. 实现无二步验证/TOTP 登录、AI Studio 验证与统一会话提交，先提供手动新增和重新登录。
6. 接入所有过期事件，增加版本校验并改造现有会话更新路径，启用自动恢复。
7. 用少量账号验证后逐步补录生产账号凭据，默认并发保持 1，按机器资源再调整。

关闭自动恢复时，已有 Cookie 与手动 VNC 路径仍可工作。回滚需先停止登录执行器，再部署旧版本；本次新增存储不能要求旧版本读取，认证文件格式继续兼容。

前端增加 `AccountsPage.vue` 及必要组件，更新中英文文案。构建资源通过项目现有构建命令生成，不直接手改构建产物。

## 15. 测试与验收标准

1. 账号管理可独立访问，原有搜索、过滤、上传、下载、删除、去重、切换及 VNC 功能无回归；未登录不能读写凭据、任务或截图。
2. 现有 150 个只有 Cookie 的账号可原样加载；补录凭据不会强制使有效会话过期；缺少凭据的过期账号有明确状态。
3. 无二步验证和 TOTP 两种登录成功；验证码临近过期时等待新周期，明确错误时有限更新；无密钥却遇到二步验证时正确结束。
4. Google 登录成功但邮箱不符、AI Studio 不可用或初始化失败时，不写入成功状态、不恢复调度。
5. 默认最多一个登录尝试运行；提高并发后不超过配置上限；同账号事件和重复操作始终只有一个未结束任务。
6. 重试等待不占用槽；暂停、恢复、取消、队列满和重启行为与文档一致，自动事件容量不足时可后续补入。
7. 故障注入覆盖永久等待的页面调用、浏览器启动、截图、关闭操作及执行器异常退出。任务在总超时与有界诊断清理后结束，执行器被回收，后续任务能开始，且请求服务正常运行。
8. 无法确认执行器终止时展示故障并限制资源增长；重建登录执行器后恢复消费，不能通过放弃清理无限创建新进程。
9. 超时后迟到成功、取消后回调、删除后回调、修改凭据或上传新 Cookie 后的旧回调均不能提交。旧 Context 更新和旧过期事件不能覆盖新会话。
10. 临时故障总计最多 3 次；密码错误、手机号验证、明确停用等立即转人工。重启不重置已消费次数或期限。
11. 恢复成功后可重新使用账号；人工禁用账号保持禁用；独立模型限流等状态不被无条件清除。
12. 列表和轮询网络响应没有密码、密钥或图片正文；仅点击显示后读取凭据或截图。截图在 7 天后清理，前端正确显示缺失或已到期。
13. 导入覆盖完整/缺失/重复批次、URL 编码、Base64 `+`、冲突密钥、无匹配账号、重复邮箱、损坏数据及不支持的 OTP 类型；不发生模糊匹配和静默覆盖。
14. 账密编辑可区分未修改与清除；CSV 密码特殊字符保持原样；导入版本冲突和重复提交有明确结果。
15. Cookie 单个下载及原有 Cookie 批量下载接口不包含密码和密钥；账号管理页批量下载的 ZIP 额外包含可重新导入的 `credentials.csv`，密码特殊字符保持原样。凭据导出复用管理员鉴权和 `no-store`，日志、截图输入框及异常响应不回显凭据。
16. 覆盖新账号成功时索引并发分配、文件/数据库提交中断及启动恢复，不能遗留伪成功、重复索引或错误关联。
17. 使用脱敏模拟页面测试状态机、标准测试向量测试 TOTP、伪时钟与可控执行器测试期限和队列，再用少量获授权账号做真实流程验收。真实凭据不提交到仓库。
18. 执行项目现有相关测试、lint 和前端构建，新增有意义的队列、恢复及导入回归测试，并记录真实页面可能变化的适用边界。

## 16. 本次范围边界

本次实现管理页、凭据维护、导入、独立登录队列、常见账密/TOTP 登录、过期恢复以及失败诊断。手机号验证、验证码图片、设备确认、企业 SSO 和未知挑战由人工接管；不承诺所有 Google 登录场景都能自动完成。

不新增额外身份验证，不建立短信接码、自动解除封禁或自动修改 Google 账号安全设置的能力。VNC 为账号重新打开人工登录环境即可，首版不要求无缝接管自动任务的原浏览器进程。完整的多实例队列消费和二维码图片识别可作为后续扩展。

## 17. 管理页操作整合

侧边栏控制台面板位于账号管理之前；账号管理只保留一个列表，统一提供搜索、重复筛选、去重、切换、单个/批量删除及下载。上传 Auth、账密/验证器导入、账密导出和 VNC 按钮位于顶部。批量启用/取消自动恢复会先验证全部选中账号的凭据版本，再统一保存；版本冲突不产生部分修改。

账密导出针对选中账号；未选择时导出全部账号。CSV 列为 `email,password,totpSecret`，没有保存的字段留空。批量下载针对选中账号，ZIP 包含已绑定账号的 `auth-N.json` 和全部选中账号的 `credentials.csv`；无会话账号仅出现在 CSV 中。单个下载仅包含会话数据。批量删除和切换复用原有连接、账号池及维护锁流程。

登录队列顶部的全局自动登录开关控制过期会话的自动恢复，状态持久化。关闭后不创建或启动自动恢复尝试；已排队任务保留，运行中的尝试完成，手动登录仍可用。每个账号的自动恢复开关也会在任务启动前检查。暂停队列仍用于暂停全部新尝试。
