# 账号自动登录与会话恢复部署

控制台的「账号管理」分页可直接访问 `/accounts`，保留 Cookie 上传、下载、批量操作、去重、切换和 `/auth` VNC 登录入口。新增邮箱/密码/TOTP 登录、凭据维护、导入、队列控制及失败诊断。所有接口沿用控制台会话鉴权。

## 运行条件

- Node.js >= 22.13；SQLite 在独立工作线程执行。
- 当前执行器使用 Linux `/proc` 与独立 POSIX 进程组进行身份验证及进程树终止。使用单个管理服务实例，不允许多个实例共享队列数据库；启动时独占锁检测重复实例。容器应启用 `init: true` 回收孤儿进程，并使用独立 PID 命名空间。跨 PID 命名空间共享队列不受支持。
- 使用与请求服务相同的 `CAMOUFOX_EXECUTABLE_PATH`。每个登录槽拥有独立执行器和浏览器，不共享 VNC 显示端口或请求池容量。默认每次尝试退出执行器；开启浏览器复用后，连续尝试共享同一槽的浏览器，每次新建 Context。并发默认 1，按额外 CPU/内存容量谨慎提高。
- 使用 NTP/chrony 等维护主机时间同步。验证器支持 SHA1、6 位、30 秒 TOTP；HOTP 和其他参数会明确拒绝。
- 挂载 `configs/auth`、`data` 为持久卷。自定义 `ACCOUNT_STORE_PATH`、`ACCOUNT_LOGIN_ARTIFACT_DIR` 时分别挂载相应路径。数据库及认证文件权限为 `0600`，截图目录为 `0700`；运行用户必须拥有这些目录。凭据可由后台任务读取，本版本采用受限本地明文存储。

## 配置与恢复

完整环境变量及默认值见 `.env.example`。正整数校验禁止用 `0` 关闭超时。控制台保存的并发数与暂停状态覆盖环境初始值，其他期限仍使用环境变量；队列面板显示生效来源。

`ACCOUNT_LOGIN_HUMANIZE=true` 默认开启有界交互节奏：开始填写前停顿 500–1100ms，点击前停顿 180–450ms，鼠标插值移动 4–10 步并点击控件内部随机位置，按下/抬起间隔 60–140ms。输入前点击聚焦并清空，逐字符发送键盘事件，每字符间隔随机 45–125ms，不批量注入凭据。TOTP 在聚焦、清空及停顿之后才生成，保留近过期窗口等待和最多一次换码规则。停顿与输入受尝试总时限、取消及单步预算约束；过长输入超时会停止，不继续提交半截密码。设为 `false` 可对照原有快速填充模式。该行为调整不保证消除 Google 验证码，也不自动处理图片验证码或修改浏览器指纹。

登录操作返回 `202` 与任务 ID，页面关闭不取消任务。同账号只存在一个未结束任务。自动恢复只对有凭据、启用自动恢复且未人工禁用的过期账号生效。队列满时保留待恢复状态，后续扫描补入。管理员可显式登录人工禁用账号，成功后仍保持禁用和独立模型限制。

模型请求收到 Google 上游 `401 UNAUTHENTICATED` 时，会将该请求使用的会话标记为过期，并沿用上述自动恢复规则。旧会话的延迟错误不能使新 Cookie 过期。成功提交新 Cookie 后恢复账号调度健康标记，保留人工禁用及模型限制。客户端断开、普通网络错误和本服务鉴权失败不触发此过期处理。该逻辑处理新增的上游错误，不追溯转换历史遗留的“异常但会话有效”账号。

控制台「全局自动登录」同时控制新增账号自动登录和过期会话自动恢复。关闭后，新增账号只保存凭据，不创建登录任务；可以先导入账密，再导入验证器，最后选择账号「批量重新登录」。关闭开关也会暂缓已经排队的自动任务，运行中的任务继续完成；手动登录不受开关限制，并可接管该账号已有的待执行自动任务。CSV 新账号默认创建，且仅新账号跟随提交时的全局自动登录配置；已有账号仅按原规则更新凭据。队列满时记录仍保存，导入结果单独显示自动登录入队警告。

状态筛选「未登录」选择已保存完整邮箱和密码、尚未建立会话的账号，包括此前登录失败的账号；验证器密钥不是必需条件，因为部分账号不需要二次验证。已有有效会话、会话已过期或缺少账密的账号不在此筛选内；过期会话可使用「已过期」筛选。登录成功、上传有效 Cookie 或人工恢复会话后，账号当前失败摘要会清除，历史失败仍保留在「任务 / 日志」中；升级重启时也会清理旧版本遗留在有效空闲会话上的失败摘要。

未登录账号也会出现在「节点池 → 账号出口」。可以在首次登录前保存单账号或批量节点绑定，不需要点击「应用」；首次登录浏览器、目标应用会话验证和登录后的请求 Context 均沿用该节点。绑定按规范化邮箱保存，获得 Cookie 编号后继续使用，重启服务后仍保留。绑定节点不可用时登录失败，不静默回退其他出口；未绑定的未登录账号使用环境代理或直连。已有 Cookie 账号修改绑定后仍需「应用」重建 Context；「应用空闲账号」及「排队应用全部」仅处理已有 Cookie 编号的账号。

临时故障最多尝试 3 次，重试等待 30/120 秒加抖动，等待不占执行槽。密码错误、手机号验证、SSO、未知挑战等进入人工处理；使用 VNC 重新打开人工登录环境。登录成功必须确认实际邮箱及项目目标应用初始化，不调用模型生成。目标应用在同一独立浏览器的新 Context 中复用原 `BrowserManager` 初始化及 `authIndex` 握手。初次登录 Context 导出状态并确认关闭后才创建验证 Context，降低页面重叠；最终身份和条款检查保持不变。该 Context 使用临时 HTTP 转发代理，将应用固定的 localhost/127.0.0.1:9998 原生 WebSocket 连接送往随机本地端口；其他网络流量沿用账号代理配置。不监听生产 9998，不进入请求连接池。提交前必须在独立 `ConnectionRegistry` 中确认真实 OPEN 连接，仅有网页成功日志不能提交会话。

正常结果先作为待提交结果上报，执行器确认所有 Context 和验证资源清理完成后才可提交并复用。超时和取消撤销提交权限，执行器收到诊断请求后最多使用截图预算，再由监督进程终止专属进程组。无法确认清理时保留故障槽并告警，限制资源增长；监控继续重试回收，确认安全后恢复容量。重启保留已消费次数和绝对恢复期限，并按执行器 PID 与启动时间检查遗留进程；无法证明归属的 PID 不会被强杀。

凭据缺失、人工处理、队列暂停均不影响其他已有有效 Cookie。关闭 `ACCOUNT_AUTO_RELOGIN_ENABLED` 仍允许手动登录和 VNC。回滚前先暂停队列并关闭执行器，再部署旧版本；新增数据库不由旧版本读取，认证 JSON 不包含密码或 TOTP。

## 独立登录浏览器复用

该优化适合账号集中失效、连续恢复的场景。默认关闭，在控制台统一配置的「账号自动登录与恢复」组开启「复用独立登录浏览器」即可热生效；也可在首次部署时通过环境变量启用。已有统一配置覆盖值优先于环境变量。

```dotenv
ACCOUNT_LOGIN_BROWSER_REUSE=true
ACCOUNT_LOGIN_BROWSER_IDLE_TIMEOUT_MS=60000
ACCOUNT_LOGIN_BROWSER_MAX_ATTEMPTS=20
ACCOUNT_LOGIN_BROWSER_MAX_AGE_MS=1800000
```

每个登录槽按需启动一个独立 Worker 和 Camoufox，连续任务复用浏览器，每次尝试创建干净 Context，Cookie 与代理按账号隔离。默认空闲 60 秒关闭；每个浏览器执行 20 次尝试或存活 30 分钟后，在任务边界重建。失败重试计入尝试数，等待不占槽，也不会无限延长空闲保留时间。正常轮换先在清理预算内尝试关闭浏览器，随后核验并回收整个进程组，避免遗留浏览器进程和临时配置目录。

成功和已知业务失败在资源清理完整后可以复用；超时、取消、浏览器异常、未知执行错误或无法确认 Context 清理时终止整个槽的专属进程组。无法确认进程已退出的槽继续占用容量并告警，不绕过上限启动新浏览器。闲置执行器的 PID 与启动身份独立持久化，服务重启时同样检查回收。

新增配置均可在统一配置页修改，运行中的尝试保留当前期限；空闲槽在队列检查或回收定时器触发时应用新策略，领取任务前也会重新检查。缩容优先关闭多余空闲槽，运行任务不强制中止。暂停队列不停止空闲回收。关闭复用后，已有运行任务完成并清理后退出，后续尝试恢复为每次启动独立执行器。

队列状态接口（现有账号队列快照）新增：

- `browsers`：执行器 ID、进程组主 PID、状态、已承接尝试数及存活时间。
- `browserMetrics`：服务本次运行累计的浏览器启动次数、启动总耗时（含执行器启动与消息传递）、复用尝试数、完成尝试数、尝试总耗时、结果上报后的清理总耗时、清理故障数及回收原因计数。故障分支的进程组清理预算可能与尝试预算相加，耗时应按实际口径比较。

上述指标不跨服务重启累积，也不包含整机或完整浏览器进程树的 CPU/内存统计。观察时结合现有服务器监控；需要定位登录资源时，用 `browsers[].pid` 作为 PGID 查找组内进程，采样整个进程组的 CPU 与内存，不能只看 Node Worker。RSS 求和会重复计入共享内存，比较时保持口径一致。

首轮保持登录并发和请求 Context 容量不变，比较集中恢复期间的浏览器启动次数、累计 CPU、内存峰值、队列排空时间及 API 延迟。观察 3—7 天后再评估是否增加请求 Context。代码优化不等于已完成生产性能验收。

回滚优先在统一配置页关闭复用，等待执行器完成并退出；部署旧版本前暂停队列并确认所有登录进程组已回收。保留任务历史、账号状态和认证文件。详细设计和验收条件见 [浏览器复用优化方案](account-login-browser-reuse-plan.md)。

## 导入与诊断

CSV 必须有表头，支持 `email,password,totpSecret` 和 `email,password,recovery_email,totp_secret`（可选字段可留空），UTF-8/BOM、引号、逗号和换行均支持，密码保持原样。预览只按规范化完整邮箱匹配；新账号默认创建，勾选“跳过”才不导入；是否自动登录以提交时的全局开关为准。预览支持“全部跳过”和“全部覆盖”，错误及未变化行保持跳过。覆盖已有不同凭据需显式选择。预览绑定控制台会话，10 分钟过期，版本冲突按行返回失败；重复提交同一预览返回原结果。

验证器支持多条迁移链接、文本文件、普通 `otpauth://totp/` 和 Base32。缺失批次不可提交，重复批次去重，无邮箱或未知邮箱手动映射或跳过。原始导入内容仅在内存中用于有期限的预览，不进入日志或数据库。

验证器导入按完整邮箱匹配已有账号：账号没有密钥时补入；相同密钥自动跳过；不同密钥必须勾选「覆盖」，否则该行失败且保留原密钥。没有对应账号时默认跳过，不创建账号；如确需绑定，可在预览中手动选择已有账号。同一份导入中邮箱重复时，后续条目标记重复并默认跳过；不同密钥的重复条目也不会自动覆盖第一条。重复的相同迁移批次只解析一次。导入验证器不直接触发登录；已有过期会话仍遵守全局及账号自动恢复开关。

列表及任务轮询不返回凭据或图片。点击显示才读取凭据；关闭编辑框清空前端秘密字段。截图仅点击查看后请求，响应 `no-store`；关闭预览或切换账号释放对象 URL。失败截图尽力遮罩所有输入字段，每账号最多 10 张，默认 7 天后清理；已清理图片返回 `410`。结构化终态任务默认保留 30 天，未结束或仍关联执行器的任务不清理。

日常备份使用 SQLite 在线备份接口，并复制认证文件与截图。跨数据库与文件的一致性通过账号状态及会话版本校验，发生并发更新时重试；无需暂停请求服务。凭据备份不使用 Cookie 下载接口。恢复备份时保留单实例和 PID 命名空间条件；人工核对残留锁及故障槽，不删除活动实例的锁文件。

### meow_us 自动备份

宿主机的 `ai-gateway-us-backup.timer` 每小时运行 `/usr/local/sbin/ai-gateway-us-backup`，对应源码为 `scripts/ops/ai-gateway-us-backup.sh`。备份保存在 `/srv/backups/ai-gateway-us`，继续上传至原有 `gdrive:meow_us-aistudio-auth-backup` 目录。

自动登录新增的持久化内容必须与原有备份一起保留：

- `aistudio/data/accounts.sqlite`：账号密码与 TOTP、账号与 Cookie 索引绑定、会话版本、登录任务及历史、全局/账号自动恢复开关、队列并发和暂停状态。
- `aistudio/data/account-login-artifacts/`：失败截图；截图元数据位于账号数据库中。
- `aistudio/auth/`：对应的 Cookie 会话文件。

脚本不停止、暂停或重启容器，也不暂停登录队列。三个 SQLite 数据库均通过 `sqlite3.Connection.backup()` 在线导出，再检查完整性；不直接复制正在使用的数据库，不归档运行期锁或认证临时文件。账号数据库与 Cookie、截图复制前后的账号状态必须一致，提交日志必须为空，并检查每个已绑定账号的 `_accountSessionVersion` 与数据库版本相符、数据库引用的截图存在。并发更新或文件消失时最多重试 5 次；仍不一致则失败，不上传不完整备份，也不通过暂停服务强制取得快照。这是针对账号状态写入协议的校验，并不表示三个数据库与所有部署文件都具有全局原子快照。

原有调度状态、代理配置、使用统计数据库、下游密钥数据库、controller 数据及部署配置继续备份，另保存备份脚本和 systemd service/timer 以便恢复。账号数据库不存在时兼容旧版本；升级后应立即手动运行一次备份服务，检查归档成员包含新增数据库及截图目录，并确认远端对象存在。备份包含敏感凭据，沿用 root 专用目录和 `0600` 归档权限。

恢复时先停止自动备份 timer 与应用，解包同一份归档中的数据库、Cookie 和截图，恢复文件权限后启动单个应用实例。正常情况下不恢复 consumer 锁；若生产目录仍有锁，只能在确认旧实例及执行器已经停止后处理。恢复后的运行中任务由服务按已有中断恢复规则处理。`ACCOUNT_STORE_PATH` 或 `ACCOUNT_LOGIN_ARTIFACT_DIR` 改为非默认路径时，须同步修改挂载和备份脚本中的对应路径。

## 验证

`npm test` 包含队列故障注入、版本提交、迁移与 CSV 导入、标准 TOTP 向量及模拟登录页面回归测试。使用 `npm run lint` 和 `npm run build:ui` 验证代码与界面。

`tests/accounts-page.test.js` 使用本地 Vite 页面和模拟 API，在 Chromium 中验证账号上传后立即刷新、清空搜索框、取消状态筛选和乱序响应保护；不会访问真实账号或外部服务。运行 `npx playwright install --with-deps chromium` 准备浏览器后，可使用 `node --test tests/accounts-page.test.js` 单独验证；未安装 Chromium 时，默认测试套件跳过这一项。

设置 `ACCOUNT_LOGIN_BROWSER_TEST_EXECUTABLE` 为部署浏览器的可执行文件路径，可运行 `node --test tests/account-login-browser.test.js`。该可选测试在真实 Camoufox 中使用完全本地响应及虚拟凭据，覆盖异步验证切换、隐藏旧输入框、新验证码输入类型、无二步验证、账号不匹配和应用初始化失败；未设置路径时跳过，不访问真实账号。目标应用验证使用原 `addInitScript` 流程，不改写文档、srcdoc、HTML Blob 或 CSP。浏览器测试还覆盖 srcdoc/Blob iframe 握手和原生连接，以及“网页输出成功日志但未建立连接”必须失败。`tests/target-session-validation.test.js` 覆盖随机端口转发、错误账号索引拒绝及账号 HTTP 代理串联。

## 首次协议、恢复邮箱与兼容输入

后台登录会自动接受来源为 `aistudio.google.com`、具有 AI Studio/Gemini 标识和已知服务条款文字的首次协议弹窗，包括同源 iframe。也支持同时包含 AI Studio 欢迎标题、服务条款和年满 18 岁及专业/商业用途确认的整页首次协议。只操作已识别协议范围内明确必需的复选框和确认按钮；年龄及用途确认即使没有 `required` 属性也会处理，不勾选可选邮件订阅。确认按钮可带装饰性箭头图标。处理发生在等待编辑器就绪期间，随后仍须验证实际登录邮箱、目标应用初始化和原生连接。未知授权、Drive 权限、地区限制、修改密码、短信、设备确认及图片验证码不自动处理。

恢复邮箱是可选凭据，仅用于 Google 明确要求确认已登记恢复邮箱地址的挑战，不读取邮件验证码。可新增、编辑或通过「清除恢复邮箱」显式移除；留空及导入空列保留原值。普通列表和导入预览仅显示是否配置及冲突状态，完整地址通过受鉴权的凭据读取入口查看。修改会更新凭据版本并取消旧任务；恢复邮箱不会写入 Cookie JSON。

对明确识别的“您为何选择使用 Google AI Studio？”可选用途问卷，仅点击同一内容范围内的“跳过”，最多两次；不选择用途或处理其他未知问卷。识别问卷后独立计算步骤预算，重复检查不会续期，且始终受整次登录的总期限约束。点击后必须确认当前问题消失，再重新等待编辑器就绪。问卷步骤超时记录为可重试的 `onboarding_timeout`，整次登录到期仍优先记录为 `attempt_timeout`。失败诊断区分 `onboarding_read`、`onboarding_skip` 和 `onboarding_wait`，并记录步骤剩余时间、整次登录剩余时间及成功执行的点击次数。

CSV 必须提供表头。继续支持 `email,password,totpSecret`，新导出（含 ZIP 中的 `credentials.csv`）采用 `email,password,recovery_email,totp_secret`。可使用 `recoveryEmail` / `recovery_email` 和 `totpSecret` / `totp_secret`；同一字段别名列内容不一致时该行失败。表头允许 BOM 和首尾空白，密码保持原样，包括空格、引号、逗号及换行。覆盖不同恢复邮箱、密码或密钥仍须显式选择。批量 CLI 支持这两种带表头格式及带换行的引用字段。

Authenticator 页面支持单输入框和六个可编辑、`maxlength=1` 的分格输入框；其他数量转人工。控件准备后生成同一验证码，保留近过期等待及明确拒绝后最多一次换码；自动提交页面会重新检查状态再决定是否点击下一步。

失败历史中的 `controls` 只包含受限控件类型和白名单按钮标签，不包含任意属性、输入值或页面正文。扫描最多 100 个控件，随登录历史的既有权限和保留期限清理。结构诊断失败不改变原失败原因。仅补充真实观察到的“控制 API 费用”非阻塞提示：可点击明确的关闭按钮，最多两次；不点击“创建支出上限”。未知欢迎页或「继续」页面仍转人工，不添加宽泛点击规则。首次等待要求页面稳定至少 1.5 秒；目标连接验证后，在最终会话上下文重新检查协议与身份，避免把弹窗后已出现的编辑器当作完成协议。

### 账号选择与停止登录

账号列表默认每页 20 条，可切换 20 / 50 / 100 条。“全选本页”仅选择当前页；翻页保留选择，所有批量动作包含其他页已选账号。“取消全选”清空全部选择，搜索及状态筛选变化也会清空选择。

密码输错时可点击“批量取消登录”：停止选中账号的排队、等待重试和运行中任务，同时停止当前批量登录尚未发出的请求，并等待已发出的请求返回后再取消其任务。结果区分取消成功、无需取消、执行器仍在停止和失败；选择与凭据保留。仍在停止的执行器会通过队列轮询跟踪，退出前不能为同一账号再次登录。

显式取消后账号进入 `manual_required`（需人工处理），不修改全局或账号自动恢复开关，服务重启及开关切换也不会自动恢复该任务。修正凭据后手动“重新登录”或“批量重新登录”继续。单任务取消遵循相同规则。

节点池可通过 `/proxy-pool` 直接访问，或从侧栏进入。窄容器下节点、订阅和账号绑定以卡片展示，保留选择、测试、编辑、删除、刷新订阅、保存绑定与应用操作；订阅地址继续脱敏显示。
