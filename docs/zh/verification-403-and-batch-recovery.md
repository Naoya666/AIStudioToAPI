# 验证403与批量恢复

Playground 上游明确返回 `Your account must be verified before it can continue using the Gemini API.`，且 HTTP 状态为403或 RPC 为 PERMISSION_DENIED / code 7 时，调度器将错误分类为 `verification_required`。普通403和无法识别的403继续使用 `risk_controlled` 退避冷却。

验证限制保存为账号的 `playground_verification`，包含首次发现时间。它阻断该账号的全部 Playground 模型，包括后续新增模型及其别名；Build 与 build-st 继续按原规则调度。它不会禁用认证、删除凭据或修改账号层级。当前失败请求在已有重试预算内换号，已在执行的并发请求可继续完成。

管理面板与匿名公示面板的次数和 Token 预算使用相同资格口径：`playground_verification` 非空的账号不贡献任何 Playground 模型的总预算、剩余预算或未知额度账号数，Build 预算独立保留。全部账号待验证时，已知模型的 PG 预算和剩余额度为 0。普通短时风控 403 仍按原规则计入理论预算，不因冷却临时扣除。

资格变化不抹除当天尝试数、已观测 Token 或历史统计。待验证账号缺失 Token 用量时，仍保留未知用量请求数，但不影响其他合格账号的剩余预算估算；合格账号自身缺失用量或预算未知时，剩余预算仍返回未知。管理员恢复账号后，重新按原层级预算减去保留的当天用量估算；恢复操作不会被当成上游已验证成功的证据。

限制随调度状态持久化，并按现有账号身份关联规则保留。重启、自动每日恢复、重置429、单模型恢复、并发成功、Build成功和重新登录均不会自动解除。管理员在完成上游验证后，可使用“恢复账号及全部模型”、批量恢复或“一键启用所有账号”解除；后者仍只作用于当前有效轮换账号。恢复只解除本地限制，不代表已确认上游验证成功；再次收到验证403会重新阻断。

升级到调度状态版本8时，仅将历史 Playground 模型记录中可明确识别的验证403迁移为待验证。普通403、Build错误和“长期403”观察标记不会被转换。现有长期403提示继续按原规则独立工作。

“账号 × 模型详情”新增“403验证”筛选、验证入口和首次发现时间提示。支持勾选账号、全选当前搜索和筛选结果、清空选择、批量禁用及批量恢复账号和全部模型。选择可跨筛选保留；账号消失或身份变化后移除失效选择，提交时也校验账号身份。

批量恢复沿用单账号恢复语义：清除调度禁用、不支持、429、冷却及验证限制，不清除历史用量或修改模型权限。有活动请求的账号恢复失败，其余账号继续处理；页面展示失败原因，并保留失败账号的选择。批量禁用停止新请求分配，已有请求继续完成。

账号管理新增“待验证”状态筛选和“待验证（Playground）”标签，与登录、恢复状态并存。列表分页与全选接口使用相同的后端筛选条件，管理员可继续使用现有凭据查看功能登录并完成验证。

管理接口 `POST /api/scheduler/accounts/batch` 需要控制台认证，请求包含整数数组 `account_ids` 和 `action: disable | enable`，可附带按编号映射的 `account_keys` 防止账号重编号后误操作。每个账号独立返回 `success` 及失败原因，失败不会中止整批。
