# Token 日额度冷却修复（2026-11-01）

依据运行手册 `meow-us-token-daily-quota-misclassification-20261101.md` 的已观测错误，`ModelScheduler` 增加以下组合的日额度识别：

- 指标为 `generativelanguage.googleapis.com/generate_content_tokens_per_model_per_user`；
- 同一额度错误行包含 `description: Generate content tokens per user per day limit exceeded`。

满足组合时归类为 `daily_quota`，沿用 `dailyResetTime` 定义的下一个太平洋时间重置点（默认午夜，包含夏令时处理）。不采用通用 `Please retry in ...` 提示，也不硬编码观测到的 11,000,000 token 上限。仅有 token 指标、分钟级限制、未知指标和通用 429 保持临时限流语义；原请求数日额度与显式 usage-limit 倒计时规则保持有效。

回归使用本地脱敏样本和假时间，覆盖三种错误消息来源、流式和非流式重试、超过 1200 秒仍冷却、账号和模型隔离、持久化重载及并发短限流/成功响应不缩短日额度冷却。2026-11-01 夏令时切换当天的样例在 `07:30Z` 失败，默认冷却至 `2026-11-02T08:00:00Z`（北京时间 11 月 2 日 16:00）。

## 上线与已有状态

本次修改只涉及代码、测试和说明，未部署生产、修改渠道控制器或修正生产调度状态。

上线采用等待下一次真实错误触发正确分类的方案：已持久化为 `temporary` 的旧槽位不会在加载时自动迁移，可能在原临时冷却到期后再尝试一次；若再次返回上述错误，则进入日额度冷却。

如需立即修正已有槽位，应另行按运行手册检查当前挂载、数据库和备份，保存手动回退快照，通过受控维护方式仅修正有明确错误证据的账号与模型。不得覆盖服务正在写入的状态文件、批量转换所有临时限流或清空其他账号冷却。
